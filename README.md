# pi-copy-code-blocks

Pi-расширение: под каждым блоком кода в транскрипте появляется кнопка
`📋 copy · js · 12L`. Клик по ней копирует **исходный** текст блока — без
терминальных артефактов, которые возникают при выделении мышью.

## Проблема

Копирование кода выделением из fullscreen-терминала снимает экранные строки, а не
исходный текст, поэтому в буфер попадают:

- отступ `markdown.codeBlockIndent` (по умолчанию два пробела) перед каждой строкой;
- пустые строки-артефакты и разрывы там, где терминал сделал soft-wrap;
- следы `CRLF` вместо `LF`.

## Что делает расширение

| Действие | Результат |
| --- | --- |
| Клик по `📋 copy · <lang> · <NL>` под блоком (fullscreen) | код блока в буфере, чистый |
| `/copycode` | список блоков последнего ответа → выбор → копирование |
| `/copycode 2` | скопировать второй блок без списка |
| `Ctrl+Alt+C` | то же, что `/copycode` (удобно, когда мышь занята) |

Метки добавляет `registerMarkdownTransformer`, то есть они видны **только в
рендерe транскрипта**: контекст модели, история сессии и `/export` остаются чистыми.

## Установка

```bash
# из git (рекомендуемый способ для пользователей)
pi install git:github.com/yxsa/pi-copy-code-blocks

# для разработки: пакет из рабочей копии, правки подхватываются после /reload
cd /path/to/pi-copy-code-blocks
pi install "$PWD"
```

Перезапусти Pi или выполни `/reload`. Проверить, что ресурс загружен: `/settings`.

## Как это работает

1. **Парсер fenced-блоков** (`scan()` в `extensions/copy-code-blocks.ts`) идёт по
   markdown и для каждого закрытого ```` ``` ````/`~~~`-блода кладёт под него
   markdown-ссылку `[📋 copy · js · 12L](picopy:<id>)`, где `id` — 6-символьный
   FNV-1a хэш содержимого. Хэш вместо счётчика нужен потому, что трансформер
   вызывается на каждом перерендере (стриминг, смена ширины, тема).
2. **Реестр** `id → { lang, code, lines }` живёт в памяти расширения, лимит
   `MAX_BLOCKS = 400` с вытеснением старых.
3. **Перехват клика**: `TuiAltScreen.prototype.handleMouseEvent` оборачивается до
   штатной обработки. Если клик попал в строку с нашей ссылкой, событие
   потребляется: так Pi не начинает выделение текста, `fullscreenCopyOnSelect` не
   затирает буфер самой меткой, а `openUrl` не пытается открыть `picopy:` в браузере.
4. **Определение цели**: `getScreenLines()` + `getOsc8LinkAtColumn(line, x)`
   (OSC8-ссылка) либо поиск `picopy:<id>` в `stripTerminalSequences(line)` для
   терминалов без гиперссылок — Pi дописывает `(picopy:<id>)` в текст строки.

## Настройки

Константы в начале `extensions/copy-code-blocks.ts`:

| Константа | Дефолт | Зачем |
| --- | --- | --- |
| `LABEL_MESSAGE_TYPES` | `["assistant"]` | добавь `"user"`, чтобы кнопки были и под кодом в твоих запросах |
| `MAX_BLOCKS` | `400` | размер реестра `id → код` |
| `SCHEME` | `"picopy"` | схема ссылки в метке |
| текст `out.push(...)` в `scan()` | `[📋 copy · js · 12L](picopy:…)` | вид кнопки; короче = меньше риск переноса по ширине |

## Ограничения

- Перехват мыши — патч прототипа `TuiAltScreen`: официального хука на мышиные
  события в транскрипте у Pi нет. На новых версиях Pi патч может потребовать правки
  (флаг `Symbol.for("pi.copy-code-blocks.patch")` защищает от двойного заворачивания
  при `/reload`, а `session_shutdown` снимает патч).
- В `tuiMode: "regular"` терминал владеет мышью — там работают только хоткей и
  `/copycode`.
- Клик по хвосту метки, перенесённому на вторую строку из-за узкого терминала, не
  ловится: метка сделана короткой специально.
- Блоки, вытесненные из реестра, копируются через `/copycode`: текст разбирается
  заново из сообщения в сессии.

## Разработка

```bash
npm install            # typescript + @types/node
npm run dev:setup      # симлинки node_modules/@earendil-works/* на глобальный Pi
npm test               # синтаксис + tsc --noEmit + node --test
```

`dev:setup` намеренно не кладёт хостовые Pi-пакеты в `dependencies` (см.
[docs/packages.md](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/packages.md):
физическая копия ломает module mapping Pi и создаёт дубли классов) — вместо них
`peerDependencies` и симлинки на установленный Pi.

Структура:

```
extensions/copy-code-blocks.ts   расширение (единственный ресурс пакета)
test/copy-code-blocks.test.ts    смоук-тесты: метки, клик, fallback, /copycode, откат патча
scripts/dev-setup.sh             симлинки Pi-пакетов для тестов и типов
scripts/verify.sh                то, что вызывает npm test
```

Тесты не трогают системный буфер обмена: `testing.setClipboardWriter()` подменяет
запись, а `TuiAltScreen.prototype.handleMouseEvent` в тестах заменяется счётчиком
вызовов, чтобы проверить, что клик мимо кнопки уходит в штатную обработку.
